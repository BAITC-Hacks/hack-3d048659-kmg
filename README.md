# Ветропрогноз

Интерактивный прототип веб-приложения для почасового прогнозирования выработки ВЭС на горизонте 24–48 часов. Он демонстрирует работу с выпусками прогноза, погодными данными и самостоятельным циклом агента: получение погоды → подготовка данных → расчёт → проверка → повторный расчёт.

Это интерфейс на искусственных данных. Бэкенд, ML-модель и реальные погодные источники пока не подключены; приложение не выполняет API-запросы. Набор примеров охватывает выпуски с 31 января по 2 февраля 2026 года и не является выполненным прогнозом за весь тестовый февраль.

## Запуск

Нужны Node.js версии 22.12 или новее и npm. Рекомендуемая версия Node.js — 24.

```bash
npm install
npm run dev
```

Откройте адрес, который появится в терминале. По умолчанию сервер разработки доступен на `http://127.0.0.1:5173`.

Сборка и локальный просмотр собранного приложения:

```bash
npm run build
npm run preview
```

Команда сборки проверяет TypeScript и создаёт статические файлы в `dist`. Сервер предпросмотра выводит свой адрес в терминал. При размещении на хостинге для прямого открытия вложенных страниц нужна переадресация неизвестных путей на `index.html`.

## Страницы и основной сценарий

| Адрес | Назначение |
| --- | --- |
| `/forecast` | Выбор турбины, выпуска и горизонта; почасовой график, сведения о выбранном часе, сравнение выпусков и демонстрационный пересчёт. |
| `/weather` | Погодные входные данные выбранного выпуска, время их выпуска и доступности, демонстрационные состояния источника. |
| `/history` | История успешных и ошибочных запусков, причина расчёта и переход к выпуску. |

1. На странице прогноза выберите одну из двух турбин, выпуск и горизонт 24 или 48 часов.
2. Выберите час, чтобы рассмотреть его мощность, ветер и температуру. Все даты и часы указаны в **UTC**.
3. Посмотрите блок «Что изменилось». Сопоставляются только одинаковые целевые часы из пересекающихся прогнозных периодов.
4. Запустите демонстрационный пересчёт и проверьте сценарии успеха и ошибки. Это локальная имитация этапов агента, а не запуск модели.
5. На странице погоды проверьте время доступности погодного выпуска и переключите демонстрационное состояние источника. В истории просмотрите результат запуска.

Выбранные турбина, выпуск и горизонт отражаются в параметрах URL `turbine`, `run` и `horizon`. Новые демонстрационные запуски сохраняются в `sessionStorage` текущей вкладки и остаются доступны после обновления страницы в ней. Серверного хранения нет: ссылка на созданный в одной вкладке запуск сама по себе не переносит его данные в другую сессию.

## Данные и ограничения демонстрации

- Начальные данные детерминированы: для каждой турбины есть четыре успешных выпуска и один пример ошибочного запуска. Каждый набор содержит 48 почасовых точек начиная со следующего часа после выпуска; выбранный горизонт определяет отображаемый период.
- Новый демонстрационный запуск получает время на три часа позже предыдущего. Это условное время сценария, не текущее время компьютера.
- Погода зависит от целевого часа, а поправка выпуска позволяет увидеть изменение прогноза для пересекающихся часов. Времена выпуска и доступности погодных данных не позже времени расчёта.
- Нормализованная мощность находится в условном диапазоне от 0 до 1. Значения искусственные: их нельзя трактовать как МВт, МВт·ч, реальную выработку или подтверждённую точность модели. Перевода в физические единицы и суммирования турбин в мощность станции нет.
- Ветер, температура и результаты работы агента также демонстрационные. Ошибочный запуск не следует считать доступным прогнозом, даже если его технический набор содержит иллюстративные точки.
- Иллюстрация в верхнем блоке сгенерирована для оформления. Она не является фотографией предоставленной ВЭС и не подтверждает расположение турбин.

## Устройство проекта

Стек: React, TypeScript, Vite, Recharts и Lucide. Шрифт Manrope включён в локальную сборку через `@fontsource-variable/manrope`; загрузка шрифта со стороннего сервиса при работе приложения не требуется.

| Файл | Содержимое |
| --- | --- |
| `src/App.tsx` | Страницы, состояние интерфейса, выбор выпуска и демонстрационные взаимодействия. |
| `src/styles.css` | Визуальное оформление, адаптивность и состояния элементов. |
| `src/data/demo.ts` | Типы, начальные данные, создание демонстрационного запуска и форматирование дат в UTC. |

## Ручная проверка

Ниже — сценарии для проверки прототипа, а не отчёт об уже пройденных тестах.

| Проверка | Ожидаемый результат |
| --- | --- |
| Экран 1440 px | Основные блоки и график читаются без перекрытий; элементы управления доступны. |
| Экран 1024 px | Компоновка перестраивается без потери функций; подписи и график остаются различимыми. |
| Экран 390 px | Нет горизонтального переполнения всей страницы; навигация, выбор выпуска и сведения о часе доступны. |
| Клавиатура | Видимый фокус, понятный порядок Tab; кнопки и переключатели работают без мыши. |
| Уменьшение движения | При включённом `prefers-reduced-motion` декоративные анимации отключены или сведены к минимуму. |
| Турбина, выпуск, горизонт | Переключение согласованно обновляет данные и URL; горизонт показывает 24 или 48 часов. |
| Сравнение выпусков | Сравниваются только общие целевые часы; отсутствие пересечения не создаёт ложных сопоставлений. |
| Успешный пересчёт | Видны этапы демонстрации, появляется новый успешный выпуск и запись в истории. |
| Ошибка пересчёта | Видна причина сбоя; ошибочный запуск не подменяет доступный успешный прогноз. |
| Погода | Переключение демонстрационных состояний источника понятно отражается в интерфейсе; временные отметки остаются различимыми. |
| Обновление вкладки | Выбор восстанавливается из URL, созданные в этой вкладке запуски — из `sessionStorage`. |
| Сборка | `npm run build` завершается успешно; страницы открываются в `npm run preview`. |

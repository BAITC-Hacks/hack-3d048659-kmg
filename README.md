# hack-3d048659-kmg

Почасовой прогноз нормализованной мощности двух турбин на 48 часов.
Единая HistGradientBoostingRegressor использует прогнозную погоду ECMWF IFS,
категориальный `turbine_id`, календарные признаки и sin/cos направления ветра.
Общая погодная точка: 43.644174, 78.537216; возвращённая Open-Meteo высота — 555 м.
Погода загружается один раз для общей точки и повторно используется обеими турбинами.

## Reproduce from scratch

Python 3.11, команды из корня репозитория. В Windows PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m src.agent.run --backtest
python -m pytest -p no:cacheprovider
```

Если активация окружения запрещена политикой PowerShell, замените `python`
на `.\.venv\Scripts\python.exe`. В Linux/macOS создайте окружение через
`python3.11 -m venv .venv`, затем `source .venv/bin/activate`.
Установка библиотек требует сети или локального wheelhouse. После установки
`--backtest` работает offline: модели и все 29 нужных погодных выпусков
закоммичены. Tests блокируют сетевые запросы при проверке кеша и реального прогноза.
Для совместимости сохранённых joblib-моделей scikit-learn закреплён на 1.9.1.

Один origin и повторный прогноз:

```powershell
python -m src.agent.run --origin 2026-01-30T19:00Z --no-llm
```

Без `--no-llm` поведение такое же: детерминированный агент — режим по умолчанию.
LLM-оркестрация опциональна и в текущую реализацию не включена. `OPENAI_API_KEY`
не нужен; отсутствие ключа не блокирует работу. `.env` не добавляется в Git.
Повторный запуск заменяет строки по ключу
`(turbine_id, forecast_origin_utc, target_time_utc)`, не создавая дубликатов.

Полное переобучение и воспроизведение оценки из исходных CSV и погодного кеша:

```powershell
python -m src.data.load
python -m src.weather.client
python -m src.features.join
python -m src.model.train
python -m src.agent.run --backtest --no-llm
python -m src.eval.backtest_jan
python -m pytest -p no:cacheprovider
```

## Результаты и модели

- `outputs/forecasts.csv`: 2784 строки = 29 origins × 2 турбины × 48 часов.
  Origins: местная полночь 2026-01-31…2026-02-28, то есть 19:00 UTC предыдущего дня.
  Файл включает отдельные цели в январе и марте на краях 48-часовых горизонтов.
- `outputs/hgb_model.joblib`: production `hgb-v2-train-before-20260201`,
  48 767 размеченных часов до 2026-02-01 00:00 UTC+05:00.
- `outputs/hgb_validation_model.joblib`: сохранённая модель до 2025-12-01.
  Только она используется для origin 2026-01-31 00:00 local: production-model
  ещё содержит недоступные на этот момент наблюдения.
- `outputs/power_curve.csv`: `turbine_id,wind_bin,power_median`; `wind_bin` —
  нижняя граница интервала 0.5 м/с. Медианы рассчитаны по измеренному ветру
  на том же обучающем срезе, что production-model. Интерполяция использует
  центры бинов; вне диапазона применяется крайнее значение.
- `outputs/agent_runs.jsonl`: шаги агента с полями
  `ts,origin_utc,step,status,message,weather_run,fallback`.
- `outputs/backtest_manifest.json`: использованные модели/выпуски по каждому origin.
- `outputs/forecasts_jan.csv`, `outputs/jan_evaluation_rows.csv`,
  `outputs/metrics.json`: отдельный январский прогон и строки для проверки метрик.
- `outputs/actuals_jan.csv`: 1488 фактических часовых значений для UI,
  колонки `turbine_id,target_time_utc,actual_power`.

**`actuals_feb.csv` получить нельзя:** исходные данные заканчиваются
2026-01-31 23:50 local. Февральские MAE/RMSE не вычисляются и не подменяются
метриками января. Исходные файлы содержат нормализованную мощность [0,1],
а не кВт. Пустые часы сохраняются как пропуски, а не нулевая мощность.
`outputs/data_profile.json` содержит актуальную статистику данных;
`outputs/data_inspection.md` — первоначальный отчёт до появления CSV.

Выходная схема остаётся ровно такой:

```csv
turbine_id,forecast_origin_utc,weather_run_utc,target_time_utc,horizon_h,predicted_power,model_version,fallback_used
```

Все временные метки — UTC с `Z`. Цель соответствует началу часового интервала
`[target_time_utc, target_time_utc+1h)`; `target=origin+horizon_h`, горизонты 1…48.
`forecasts_mock.csv` остаётся отдельной синтетической фикстурой и не участвует в оценке.

## Leakage controls

1. Сырые метки трактуются как фиксированный UTC+05:00, затем переводятся в UTC.
   Часовая средняя доступна только через час после метки начала интервала.
2. Обучение ограничено `time < cutoff` и `available_at_utc <= cutoff`, где
   `cutoff <= HISTORY_END = 2026-01-31T19:00Z`. Часы без целевой мощности
   исключаются. HGB может обучаться на размеченных часах с пропусками погодных признаков.
3. Перед каждым прогнозом проверяется, что обучающие наблюдения модели
   доступны к origin. Модель, обученная на более поздних данных, отклоняется.
4. Выбирается последний цикл 00/06/12/18 UTC с `run+6h <= origin`.
   Шесть часов — заданная модель задержки доступности, не измеренное время публикации.
   Для прогнозов и январской оценки используется только Single Runs,
   без фактической будущей погоды и без реанализа.
5. Погодные признаки обучения берутся из Historical Forecast (сшитый архив
   коротких прогнозов). Январские проверочные признаки берутся из конкретных
   исторических выпусков с нужными сроками. Различие распределений сроков
   обучения и прогноза остаётся ограничением модели.
6. Измеренные ветер, температура и будущая мощность не входят в признаки HGB.
   Persistence — последнее наблюдение, доступное к origin, неизменное на все 48 часов.
7. Fallback: полный выбранный выпуск → полный предыдущий выпуск (−6h) →
   эмпирическая кривая по полному ветру из самого свежего полученного выпуска →
   persistence. Все варианты повторно проверяют доступность. Начиная с
   предыдущего выпуска `fallback_used="true"`; метод отражается в журнале,
   а для кривой/persistence — также в `model_version`.
   Если использован persistence, `weather_run_utc` обозначает последний
   полученный или выбранный допустимый цикл; погода при этом не используется.
8. Перед сохранением проверяются обе турбины, 48 уникальных горизонтов,
   отсутствие NaN, границы [0,1], UTC, `target=origin+h` и доступность выпуска.

## Январские метрики Single Runs

Модель оценки обучена до 2026-01-01 00:00 UTC+05:00. Origins — местные
полуночи 2026-01-01…2026-01-30. Все три метода оценены на одних и тех же
2878 строках (по 1439 на турбину). Две цели на границе февраля исключены
из-за отсутствия фактических значений. Одна цель с разными origins считается
отдельными прогнозами. На этом прогоне fallback не понадобился.
Источник таблиц — `outputs/metrics.json`, `weather_source="single_runs"`.

| Турбина | Метод | MAE | RMSE |
|---|---|---:|---:|
| 1 | model | 0.1644 | 0.2214 |
| 1 | power_curve | 0.1573 | 0.2313 |
| 1 | persistence | 0.3398 | 0.4623 |
| 2 | model | 0.1677 | 0.2271 |
| 2 | power_curve | 0.1602 | 0.2355 |
| 2 | persistence | 0.3366 | 0.4594 |

По горизонту, обе турбины вместе: 1440 строк для 1–24h, 1438 для 25–48h.

| Горизонт, ч | Метод | MAE | RMSE |
|---|---|---:|---:|
| 1-24 | model | 0.1556 | 0.2072 |
| 1-24 | power_curve | 0.1492 | 0.2199 |
| 1-24 | persistence | 0.3215 | 0.4562 |
| 25-48 | model | 0.1765 | 0.2401 |
| 25-48 | power_curve | 0.1683 | 0.2461 |
| 25-48 | persistence | 0.3549 | 0.4655 |

Кривая мощности лучше HGB по MAE, HGB лучше по RMSE; оба лучше persistence.
Ранние `validation_metrics.csv` относятся к декабрю–январю со сшитым
погодным рядом и не заменяют эту оценку по выпускам.

## Third-party libraries and data sources

- pandas, numpy: чтение, агрегация, признаки и расчёты.
- scikit-learn: HistGradientBoostingRegressor и метрики.
- requests: HTTP; pyarrow: Parquet; PyYAML: конфигурация.
- streamlit, plotly: зависимости интерфейса команды.
- openai: библиотека для опциональной LLM-интеграции, в текущем агенте не вызывается.
- pytest: тесты; python-dotenv: поддержка локальной конфигурации окружения.
- joblib и threadpoolctl (зависимости scikit-learn): артефакты моделей и управление потоками.
- Погода: [Open-Meteo Historical Forecast API](https://open-meteo.com/en/docs/historical-forecast-api)
  для обучающего ряда; [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api)
  для архивных выпусков прогнозов. Модель — ECMWF IFS (`ecmwf_ifs`).
- Наблюдения: предоставленные командой `data/raw/turbine_1.csv` и `turbine_2.csv`.

Parquet-кеш имеет JSON-метаданные: URL и параметры запроса, выбранную модель,
единицы (ветер в м/с), координаты, возвращённую высоту, пропуски и время получения.
Общая точка использует DEM Open-Meteo (`elevation: null`); высота сохранена в метаданных.

## Проверка часового пояса

Анализ без изменения данных: Pearson между часовым измеренным ветром и
Historical Forecast `wind_speed_100m`. Положительный сдвиг переносит погодные
метки позже: при +1h наблюдение в t сравнивается с погодой в t−1h.
Для пяти сдвигов внутри каждой строки использована одна общая выборка.
Разделение периодов — 2024-03-01 00:00 при фиксированном UTC+05:00.

| Период | Турбина | Часов | −2h | −1h | 0h | +1h | +2h |
|---|---:|---:|---:|---:|---:|---:|---:|
| До 2024-03-01 | 1 | 8515 | 0.614833 | 0.699775 | 0.762571 | 0.766356 | 0.722784 |
| До 2024-03-01 | 2 | 8399 | 0.616943 | 0.702001 | 0.763262 | 0.767326 | 0.724613 |
| С 2024-03-01 | 1 | 15241 | 0.648770 | 0.735250 | 0.790836 | 0.789526 | 0.746429 |
| С 2024-03-01 | 2 | 16598 | 0.640837 | 0.728084 | 0.784728 | 0.783551 | 0.739051 |

До границы максимум при +1h лишь на 0.0038–0.0041 выше 0h. Недельный блочный
bootstrap (1000 повторов, seed=42, общие пары для 0h/+1h) даёт 95% интервалы
разности корреляций: [−0.00385, 0.01129] и [−0.00399, 0.01159]. Оба включают
ноль. После границы максимум при 0h. Явного подтверждения другого часового
пояса нет; парсинг не изменён, применяется фиксированный UTC+05:00 ко всей
истории, а не исторические правила зоны Asia/Almaty.
